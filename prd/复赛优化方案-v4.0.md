## 1. 执行摘要

### 1.1 一句话方案

**BioQuest v4.0 = 初赛刷题平台底座 + v3.1 AI 课堂精选深化 + 身心健康附加赛题有机融合**，在 20 天内交付一个"AI 老师能操作 UI 讲课、AI 同学会苏格拉底式提问、学生有可量化的学习画像与情绪节律追踪"的完整生物学习伙伴，并兼顾青少年身心健康附加赛题（5 万元专项奖可叠加）。

### 1.2 核心数字

| 维度 | 数字 |
|---|---|
| 复赛开发窗口 | 20 天（2026.07.21 — 08.09），扣除作者集训营占用后实际有效开发约 14 天 |
| 核心深化模块数 | 4 个（从 v3.1 的 12+ 收缩到 4） |
| 新增代码估计 | 约 6000-8000 行（含 6 张新 Supabase 表、4 个新 JS 模块、3 个升级模块） |
| 题库规模 | 330+ → 500+（含 AI 变式题入库沉淀） |
| 评审四维目标 | 创新性 ≥ 8.5 / 技术实现 ≥ 8.5 / 完成度 ≥ 9.0 / 场景价值 ≥ 8.5 |
| 双赛道叠加 | 学习工作（主）+ 青少年身心健康（附加）|
| 月运营成本 | ≤ 0 元（Supabase 免费版 + 用户自配 LLM Key） |

### 1.3 战略取舍三句话

1. **做减法胜过做加法**：v3.1 的 12+ 模块在 20 天内无法做扎实，复赛最低合格标准是"完整可体验"而非"功能多"。砍掉 3D、协作实验台、Arena PvP、生物伦理研讨室、离线 AI 等 P2 模块，集中火力把"AI 课堂 + 苏格拉底导师 + 学习 DNA + 情绪节律"四件事做到评审愿意反复体验。
2. **附加赛题不是装饰是骨架**：青少年身心健康附加赛题不能做成"挂个心理测试按钮"，必须渗透到学习流程——把"学习压力自检、番茄节律情绪追踪、AI 学伴共情对话"做成 BioQuest 的内嵌能力，让"身心健康"成为产品价值主张的一部分，而非营销标签。
3. **合规优先于炫技**：复赛明确要求"延续初赛方向 + 部署可体验 + 演示视频必交 + Session ID ≥ 3"。任何不能在 8 月 9 日前稳定跑通的功能都不做，宁可少一个亮点，不可有一个崩点。

### 1.4 三大差异化创新点（评审 5 秒能记住的）

1. **AI 老师操作 UI 讲课**（借鉴 OpenMAIC 但纯前端实现）：AI 老师的 LLM 输出含 `[ACTION:highlight_animation_step:mitosis:3]` 这类动作指令，前端事件总线解析后让 AI 真的能"高亮动画第 3 步、点亮知识图谱节点、在白板画 DNA 双螺旋"——这不是聊天机器人，是会操作界面的老师。
2. **学习 DNA + 情绪节律双画像**：学习数据可视化成 32 位 ATGC 碱基序列（已有），新增"情绪节律曲线"——每日学习前后的情绪打卡，AI 识别"周三下午正确率骤降 12%"这类节律，给出"今天先做 15 分钟有氧再练遗传"的个性化建议。把生物学知识用在生物学习者身上。
3. **苏格拉底式 AI 同学**（不是 AI 老师）：初赛已有 4 模式 AI 导师，复赛升级为"AI 同学"角色——不直接给答案，用提问引导学生自己推导。配套"提示等级"按钮（L1 提问 / L2 提示 / L3 部分答案 / L4 完整答案），让学生掌握求助的主动权，缓解 AI 依赖。

## 2. 复赛规则合规性分析与战略对齐

### 2.1 复赛三大铁律 vs BioQuest 现状

| 复赛铁律 | 要求 | BioQuest 现状 | 合规判定 |
|---|---|---|---|
| 延续初赛 | 与初赛创意方向一致的完整作品 | 初赛是生物竞赛学习平台，v4.0 是同方向的深化升级 | ✅ 合规 |
| TRAE 开发可核验 | ≥ 3 个 Session ID + 关键步骤截图 ≥ 3 张 | 初赛已积累 3+ Session ID，复赛新增 Session 纳入文档 | ✅ 合规 |
| 完整用户路径 | 核心功能齐全、必要页面完备、结构稳定 | 初赛已有 13 个核心模块路由，复赛在此基础上深化 | ✅ 合规 |
| 软件部署可体验 | 评审可直接打开使用 | `bio.dada.im` 已部署，复赛沿用并迭代 | ✅ 合规 |
| 演示视频必交 | 1-5 分钟录屏展示核心流程 | 初赛已有视频，复赛需重录展示新功能 | ⚠️ 待补 |
| 不可替代体验入口 | 演示视频不能替代软件本身 | 软件本身可访问，视频仅为兜底 | ✅ 合规 |

**结论**：合规性无致命风险，但需在复赛帖中明确论证"v4.0 是初赛 Demo 的自然演进而非另起炉灶"——论证逻辑见 §6.1。

### 2.2 评审四维对齐策略

复赛通用赛道评审四维（创新性 / 技术实现 / 产品完成度 / 商业化与场景价值），BioQuest v4.0 的对齐策略：

| 评审维度 | 权重估计 | BioQuest v4.0 强化点 |
|---|---|---|
| **创新性** | ~25% | AI 老师操作 UI 事件总线 + 学习 DNA + 情绪节律双画像 + 苏格拉底 AI 同学 |
| **技术实现** | ~30% | 纯前端 LLM 编排（Per-stage routing）+ FSRS/IRT/BKT 三引擎 + OCR 双引擎 + 事件总线架构 |
| **产品完成度** | ~30%（复赛侧重点）| 13 个核心模块全部可体验 + 4 个深化模块端到端跑通 + 部署稳定 + 无严重 bug |
| **商业化与场景价值** | ~15% | 学习工作赛道刚需 + 青少年身心健康附加赛题（5 万专项奖叠加）+ 教师模式 B 端潜力 |

### 2.3 附加赛题叠加策略

**主赛道**：学习工作（与初赛一致，必须保留）

**附加赛题选择**：青少年身心健康（5 万元专项奖可叠加）

**为什么选身心健康而非其他三个附加赛题**：

| 附加赛题 | 与 BioQuest 契合度 | 选择理由 |
|---|---|---|
| 智慧助老 | 低 | 用户人群不重叠，需另起模块 |
| **青少年身心健康** | **极高** | **目标用户即青少年（高中生），学习压力是身心健康核心议题，可有机融合** |
| 古籍活化 | 无 | 与生物学科无关 |
| 非遗创新 | 无 | 与生物学科无关 |

**身心健康如何有机融合**（不是挂按钮）：

1. **学习压力自检**：仪表盘新增"学习压力指数"卡片，基于近 7 日学习时长、正确率波动、番茄钟完成率、睡眠打卡（可选）综合计算
2. **情绪节律追踪**：每日学习前/后双次情绪打卡（5 级表情 + 自由文本），AI 生成周度情绪节律报告
3. **AI 学伴共情**：苏格拉底 AI 同学在检测到学生连续答错 5 题或情绪低落时，主动切换为"共情模式"——不再追问，而是说"看起来今天状态不太好，要不先休息 5 分钟？遗传学明天再战"
4. **番茄节律优化**：基于个人情绪节律数据，AI 推荐最佳学习时段（如"你的正确率在上午 10 点最高，建议把模考安排在这个时段"）
5. **危机干预通道**：检测到自伤/自杀关键词立即弹出 12320 心理援助热线 + 转介专业资源

## 4. 市场与竞品再调研（初赛公示后的反推）

### 4.1 初赛同赛道（学习工作）优秀作品反推

基于 7 月初赛公示期间的社区观察，学习工作赛道呈现以下特征：

| 作品类型 | 数量估计 | 拥挤度 | BioQuest 差异化空间 |
|---|---|---|---|
| 志愿填报工具（高考/中考）| 3+ | 🔴 高度饱和 | 不进入 |
| 通用 AI 学习助手 | 5+ | 🟡 中度饱和 | 不进入通用赛道 |
| 学科专精工具（生物/化学/物理）| 2-3 | 🟢 蓝海 | **BioQuest 占位** |
| 编程学习平台 | 4+ | 🟡 中度饱和 | 不进入 |
| 语言学习工具 | 3+ | 🟡 中度饱和 | 不进入 |

**关键洞察**：学科专精的 AI 学习工具是初赛蓝海，BioQuest 作为唯一深耕生物竞赛的纯前端方案，在复赛有天然差异化优势。复赛策略应是**做深生物**而非扩展到其他学科。

### 4.2 直接竞品分析

## 5. 用户群体深度画像与身心健康发展空间

### 5.1 核心用户画像（复赛精修版）

#### 画像 A：李同学（高一，日常学习者，主力用户）

- **背景**：16 岁，沿海城市重点中学高一，住校，每周回家一天
- **设备**：学校机房 PC（Chrome）+ 家里旧安卓机
- **生物水平**：课内 80 分左右，对遗传学感兴趣但听不懂减数分裂细节
- **痛点**：
  - 课本上的减数分裂图是静态的，前后期变化看不懂
  - 学校实验室器材老旧，色素提取实验做不出明显结果
  - 不知道自己哪里薄弱，盲目刷题效率低
  - 晚自习 9 点后注意力涣散，但不知如何安排学习节奏
- **使用 BioQuest 的场景**：
  - 周日下午回家打开 `bio.dada.im`，先做 15 分钟每日一题
  - 用 Canvas 动画看一遍减数分裂全过程，AI 老师讲解时高亮"交叉互换"步骤
  - 做一组遗传学专项练习，错题自动进入错题本
  - AI 同学苏格拉底式问她"如果交叉互换不发生，子代基因型组合会怎样？"
  - 仪表盘显示她本周正确率周三下午最低，建议她周三下午做轻松的卡片复习
- **身心健康诉求**：住校压力大，希望 AI 学伴能在她连续答错时给予鼓励而非压力

#### 画像 B：张同学（高二，竞赛冲刺者）

- **背景**：17 岁，准备 2026 年 8 月全国生物学联赛
- **生物水平**：课内 95+，联赛目标省一
- **痛点**：
  - 联赛新赛制（72 题 MTF）真题难找，市面无免费对齐工具
  - 错题复盘耗时长，AI 解析质量参差
  - 备考压力大，情绪波动明显，但不愿找心理老师
- **使用 BioQuest 的场景**：
  - 每天做一套 72 题模考，限时 150 分钟
  - 错题本 OCR 录入纸质错题，AI 分析错因
  - 学习 DNA 显示他遗传学维度突出但生态学薄弱
  - 情绪节律曲线显示他模考成绩在周二/周四较低，AI 建议调整作息
- **身心健康诉求**：备考焦虑，需要 AI 学伴识别情绪信号并适时减负

#### 画像 C：王老师（中学生物教师）

- **背景**：35 岁，二线城市普通中学高二生物教师，带 2 个班共 80 人
- **痛点**：
  - 班级学生水平参差，难以个性化指导
  - 实验课器材不足，无法演示所有考点实验
  - 学情监控靠手动统计，效率低
- **使用 BioQuest 的场景**：
  - 教师模式批量生成 8 位用户码加学生
  - 查看班级 DNA 矩阵，一屏看清 80 人强弱分布
  - 用 AI 课堂生成"光合作用"完整课，投屏到教室大屏教学
- **身心健康诉求**：关注学生备考压力，希望工具能减轻而非加重学生负担

### 5.2 身心健康附加赛题的有机融合点

**核心原则**：身心健康不是孤立模块，而是渗透到学习全流程的"节律感知"能力。

| 融合点 | 实现方式 | 附加赛题契合度 |
|---|---|---|
| **情绪节律追踪** | 每日学习前/后双次情绪打卡（5 级表情 + 自由文本），存储到 Supabase `mood_logs` 表 | ⭐⭐⭐⭐⭐ |
| **学习压力指数** | 仪表盘卡片，基于近 7 日学习时长、正确率波动、番茄完成率综合计算 | ⭐⭐⭐⭐⭐ |
| **AI 学伴共情模式** | 苏格拉底 AI 同学检测连续答错 5 题或情绪低落时，切换为共情对话 | ⭐⭐⭐⭐⭐ |
| **番茄节律优化** | AI 基于个人情绪节律推荐最佳学习时段 | ⭐⭐⭐⭐ |
| **危机干预通道** | 检测自伤/自杀关键词 → 12320 热线 + 转介 | ⭐⭐⭐⭐⭐ |
| **学习 DNA + 情绪 DNA** | 学习 DNA 旁边并列"情绪 DNA"，可视化情绪节律模式 | ⭐⭐⭐⭐ |
| **AI 课堂节奏调节** | 课堂中检测学生注意力（答题速度变化），动态调整讲解节奏 | ⭐⭐⭐ |

### 5.3 身心健康功能的伦理与合规边界

**必须明确的边界**（苛刻批评者视角）：

1. **非医疗器械声明**：BioQuest 不是医疗器械，不诊断、不处方、不替代专业心理咨询
2. **数据隐私**：情绪数据存储在用户 Supabase 个人 schema（RLS 保护），不上传到任何第三方
3. **危机干预责任**：检测到自伤关键词必须立即弹出 12320 热线，但不尝试 AI 自杀干预（这是专业人士的工作）
4. **未成年人保护**：考虑到核心用户含 16-18 岁高中生，情绪数据不得用于商业推荐
5. **AI 共情的度**：AI 学伴不假装是真人，不建立"虚拟亲密关系"，明确告知"我是 AI 学伴，不是心理咨询师"

### 6.4 苛刻批评者：对 v3.1 的尖锐质疑

**质疑 1：v3.1 的"AI 课堂"是否会被评审认为是 OpenMAIC 的复制？**

- 风险：v3.1 PRD 明确写"借鉴 OpenMAIC"，评审可能质疑创新性
- 应对：v4.0 在文档与产品中突出三点差异——
  1. **生物专精**：OpenMAIC 是通用课堂，BioQuest 是生物专精（FSRS/IRT/BKT 三引擎 + 40 节点知识图谱）
  2. **纯前端**：OpenMAIC 是 Next.js 全栈，BioQuest 是纯前端（用户自配 Key，零服务器）
  3. **身心健康融合**：OpenMAIC 无身心健康维度，BioQuest 独有情绪节律 + 共情 AI

**质疑 2：20 天能做完 4 个深化模块吗？**

- 风险：v3.1 的 P0 就要 4 周，v4.0 即使砍到 4 模块仍有工作量
- 应对：见 §11 时间线，按"核心-增强-打磨"三层优先级，核心功能 7 天内跑通，剩余 13 天深化
- 兜底：若时间不够，砍模块 4 的"番茄节律优化"和"情绪 DNA"，保留"情绪打卡 + 压力指数 + 共情模式 + 危机干预"四个最小可行点

**质疑 3：情绪节律是否会被批为"伪科学"？**

- 风险：评审可能质疑"学习压力指数"的算法科学性
- 应对：
  1. 算法基于公开研究（学习负荷理论 Sweller 1988、心率变异性的情绪关联等）
  2. 明确标注"启发式估算，非临床诊断"
  3. 不给出医疗建议，只给学习节奏建议
  4. 文档中列出参考文献

**质疑 4：AI 老师操作 UI 的事件总线在 LLM 输出不稳定时如何降级？**

- 风险：LLM 可能不按 `[ACTION:...]` 格式输出，导致动作指令解析失败
- 应对：
  1. 严格 system prompt 约束 + JSON schema 校验
  2. 失败降级为纯文字讲解（不崩）
  3. 提供"动作预览"——AI 老师生成大纲后，前端先展示动作序列，再执行
  4. Session ID 中保留失败案例，证明降级路径有效

**质疑 5：身心健康附加赛题的评审是另一组人，会不会觉得"挂羊头"？**

- 风险：附加赛题评审可能质疑 BioQuest 的身心健康只是装饰
- 应对：
  1. 文档中专设 §5 论证身心健康与生物学习的内在关联（学习科学 + 教育心理学）
  2. 产品中让身心健康功能"看得见、用得上、有数据"——不是按钮，是仪表盘卡片 + 日常打卡 + AI 主动共情
  3. 在复赛帖与问卷中明确标注"参加青少年身心健康附加赛题"

## 7. 核心功能模块设计（精选深化 4 大模块）

### 7.1 模块 1：AI 生物课堂（AI Biology Classroom）

#### 7.1.1 用户故事

> 李同学点击知识图谱的"光合作用"节点 → 选择"生成一节 AI 课堂" → 5 秒内 AI 老师生成课堂大纲（4 个 scene）→ 进入课堂播放器 → AI 老师口述讲解 + Canvas 动画同步播放 + 第 3 步高亮"类囊体膜" → 学霸同学提问"为什么 C4 植物有花环结构" → 主讲老师解答 → 推送 3 道相关测验题 → 课堂结束，更新学习 DNA。

#### 7.1.2 输入方式（3 种）

| 输入方式 | 触发位置 | 示例 |
|---|---|---|
| 知识图谱节点点击 | `/knowledge-graph` 节点右键菜单 | 点击"光合作用" → "生成课堂" |

#### 7.3.1 学习 DNA（升级 v3.0 §2.7）

```javascript
// 学习 DNA 生成算法
function generateLearningDNA(userStats) {
  const modules = ['cellular', 'genetics', 'ecology', 'biochem'];
  const bases = ['A', 'T', 'G', 'C'];
  let sequence = '';
  
  for (let i = 0; i < 32; i++) {
    const moduleIdx = i % 4;  // 每 4 位一轮，覆盖 4 模块
    const module = modules[moduleIdx];
    const mastery = userStats.moduleStats[module]?.mastery || 0;
    const base = bases[moduleIdx];
    sequence += base;
    // 亮度由 mastery 决定（CSS 中通过 opacity 实现）
  }

    sequence,

}
```

```javascript
function generateMoodDNA(moodLogs) {

  const slots = 32;
  const moodBases = { focused: 'A', tired: 'T', excited: 'G', down: 'C' };
  let sequence = '';
  
  for (let i = 0; i < slots; i++) {
    const slot = moodLogs[i];
    if (!slot) {
      sequence += '?';  // 未打卡
    } else {
      sequence += moodBases[slot.dominantMood] || 'A';
    }
  }
  
  return { sequence, moodPattern: analyzePattern(sequence) };
}
```

#### 7.4.2 学习压力指数

**算法**（启发式，非临床诊断）：

```javascript
function calculateStressIndex(userStats, moodLogs) {
  const factors = {
    // 学习强度（近 7 日平均日学习时长）
    studyIntensity: normalize(userStats.dailyAvgMinutes, 0, 360),  // 0-6h 映射 0-1
    
    // 正确率波动（近 7 日标准差）
    accuracyVolatility: normalize(userStats.accuracyStdDev, 0, 0.3),
    
    // 番茄完成率
    pomodoroCompletionRate: 1 - (userStats.pomodoroCompleted / userStats.pomodoroPlanned),
    
    // 情绪低落频率
    lowMoodFrequency: countLowMoods(moodLogs, 7) / 14,  // 14 = 7天×2次
    
    // 睡眠规律性（可选，用户自报）
    sleepIrregularity: userStats.sleepIrregularity || 0.5
  };
  
  // 加权求和
  const weights = {
    studyIntensity: 0.2,
    accuracyVolatility: 0.25,
    pomodoroCompletionRate: 0.15,
    lowMoodFrequency: 0.3,
    sleepIrregularity: 0.1
  };
  
  const stressIndex = Object.entries(factors)
    .reduce((sum, [key, value]) => sum + value * weights[key], 0);
  
  return {
    score: Math.round(stressIndex * 100),  // 0-100
    level: stressIndex < 0.3 ? 'low' : stressIndex < 0.6 ? 'moderate' : 'high',
    mainFactor: getMainFactor(factors, weights),
    recommendation: getRecommendation(stressIndex, factors)
  };
}
```

#### 8.2.3 LLM 输出解析与降级

```javascript
function parseTeacherOutput(rawOutput) {
  const actions = [];
  const textParts = [];
  
  // 正则提取 [ACTION:type:param]
  const actionRegex = /\[ACTION:(\w+):([^\]]+)\]/g;
  let lastIndex = 0;
  let match;
  
  while ((match = actionRegex.exec(rawOutput)) !== null) {
    // 收集动作前的文本
    if (match.index > lastIndex) {
      textParts.push(rawOutput.slice(lastIndex, match.index));
    }
    
    const [_, type, param] = match;
    actions.push(parseAction(type, param));
    lastIndex = match.index + match[0].length;
  }
  
  // 收集剩余文本
  if (lastIndex < rawOutput.length) {
    textParts.push(rawOutput.slice(lastIndex));
  }
  
  return {
    text: textParts.join('').trim(),
    actions: actions.filter(a => a !== null)  // 过滤无效动作
  };
}

function parseAction(type, paramStr) {
  try {
    switch (type) {
      case 'highlight_animation_step':
        const [module, step] = paramStr.split(':');
        return { type, module, step: parseInt(step) };
      
      case 'highlight_kg_node':
        return { type, nodeId: paramStr };
      
      case 'whiteboard_draw':
        const commands = JSON.parse(paramStr);
        return { type, commands };
      
      case 'tts_speak':
        const [text, role] = paramStr.split('|');
        return { type, text, role: role || 'teacher' };
      
      // ... 其他动作类型
      
      default:
        console.warn(`Unknown action type: ${type}`);
        return null;
    }
  } catch (err) {
    console.warn(`Failed to parse action: ${type}:${paramStr}`, err);
    return null;  // 降级：跳过无效动作，继续执行文本
  }
}
```

### 8.4 自动重试机制（借鉴 OpenMAIC PR #788）

```javascript
async function withRetry(fn, { maxRetries = 3, backoff = 'exponential' } = {}) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await fn();
    } catch (err) {
      const isTransient = err.status === 429 || 
                         err.status >= 500 || 
                         err.name === 'NetworkError';
      
      if (!isTransient || i === maxRetries - 1) {
        throw err;
      }
      
      const delay = backoff === 'exponential' 
        ? 1000 * Math.pow(2, i)   // 1s, 2s, 4s
        : 1000 * (i + 1);         // 1s, 2s, 3s
      
      console.warn(`Retry ${i + 1}/${maxRetries} after ${delay}ms: ${err.message}`);
      await new Promise(r => setTimeout(r, delay));
    }
  }
}
```

### 8.6 TTS 三层方案（v4.0 仅做 L1）

```javascript
// tts.js 升级版
class TTSEngine {
  constructor() {
    this.synthesis = window.speechSynthesis;
    this.voices = this.loadVoices();
    this.currentUtterance = null;
  }
  
  loadVoices() {
    const voices = this.synthesis.getVoices();
    return {
      teacher: voices.find(v => v.lang === 'zh-CN' && v.name.includes('Female')) || voices[0],
      top_student: voices.find(v => v.lang === 'zh-CN' && v.name.includes('Male')) || voices[0],
      confused_student: voices.find(v => v.lang === 'zh-CN') || voices[0]
    };
  }
  
  speak(text, role = 'teacher') {
    if (!this.synthesis) {
      console.warn('SpeechSynthesis not supported');
      return;
    }
    
    this.stop();  // 停止当前朗读
    
    const utterance = new SpeechSynthesisUtterance(text);
    utterance.voice = this.voices[role];
    utterance.rate = 0.95;  // 略慢，便于学习
    utterance.pitch = role === 'teacher' ? 1.0 : 1.1;
    
    this.currentUtterance = utterance;
    this.synthesis.speak(utterance);
  }
  
  stop() {
    if (this.synthesis.speaking) {
      this.synthesis.cancel();
    }
  }
  
  isSupported() {
    return 'speechSynthesis' in window;
  }
}
```

```javascript
// js/event-bus.js（完善版）
class EventBus {
  constructor() {
    this.listeners = new Map();
  }
  
  on(event, callback) {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, new Set());
    }
    this.listeners.get(event).add(callback);
    return () => this.off(event, callback);  // 返回取消订阅函数
  }
  
  off(event, callback) {
    if (this.listeners.has(event)) {
      this.listeners.get(event).delete(callback);
    }
  }
  
  async emit(event, data) {
    if (!this.listeners.has(event)) {
      console.warn(`No listeners for event: ${event}`);
      return;
    }
    
    const callbacks = Array.from(this.listeners.get(event));
    const results = await Promise.allSettled(
      callbacks.map(cb => {
        try {
          return cb(data);
        } catch (err) {
          console.error(`Listener error for ${event}:`, err);
          return null;
        }
      })
    );
    
    return results.map(r => r.value);
  }
  
  once(event, callback) {
    const unsubscribe = this.on(event, async (data) => {
      unsubscribe();
      return await callback(data);
    });
    return unsubscribe;
  }
}

// 全局单例
window.EventBus = new EventBus();
```

### 13.2 AI 老师输出解析

```javascript
// js/classroom.js 片段
function parseTeacherOutput(rawOutput) {
  const actions = [];
  const textParts = [];
  
  const actionRegex = /\[ACTION:(\w+):([^\]]+)\]/g;
  let lastIndex = 0;
  let match;
  
  while ((match = actionRegex.exec(rawOutput)) !== null) {
    if (match.index > lastIndex) {
      textParts.push(rawOutput.slice(lastIndex, match.index).trim());
    }
    
    const [_, type, paramStr] = match;
    const action = parseAction(type, paramStr);
    if (action) {
      actions.push(action);
    }
    lastIndex = match.index + match[0].length;
  }
  
  if (lastIndex < rawOutput.length) {
    textParts.push(rawOutput.slice(lastIndex).trim());
  }
  
  return {
    text: textParts.filter(t => t.length > 0).join('\n'),
    actions
  };
}

function parseAction(type, paramStr) {
  try {
    switch (type) {
      case 'highlight_animation_step': {
        const [module, step] = paramStr.split(':');
        return { type, module, step: parseInt(step, 10) };
      }
      case 'highlight_kg_node':
        return { type, nodeId: paramStr.trim() };
      case 'highlight_kg_subgraph':
        return { type, nodeIds: paramStr.split(',').map(s => s.trim()) };
      case 'whiteboard_draw':
        return { type, commands: JSON.parse(paramStr) };
      case 'whiteboard_clear':
        return { type };
      case 'quiz_push':
        return { type, questionIds: paramStr.split(',').map(s => s.trim()) };
      case 'tts_speak': {
        const [text, role] = paramStr.split('|');
        return { type, text: text.trim(), role: (role || 'teacher').trim() };
      }
      case 'tts_pause':
        return { type };
      case 'navigate':
        return { type, route: paramStr.trim() };
      case 'next_scene':
        return { type };
      case 'prev_scene':
        return { type };
      default:
        console.warn(`Unknown action type: ${type}`);
        return null;
    }
  } catch (err) {
    console.warn(`Failed to parse action ${type}:${paramStr}`, err);
    return null;
  }
}

async function executeActions(actions) {
  for (const action of actions) {
    try {
      switch (action.type) {
        case 'highlight_animation_step':
          await window.EventBus.emit('bio-animation:highlight_step', {
            module: action.module,
            step: action.step
          });
          break;
        case 'highlight_kg_node':
          await window.EventBus.emit('knowledge-graph:highlight_node', {
            nodeId: action.nodeId
          });
          break;
        case 'whiteboard_draw':
          await window.EventBus.emit('whiteboard:draw', {
            commands: action.commands
          });
          break;
        case 'tts_speak':
          await window.EventBus.emit('tts:speak', {
            text: action.text,
            role: action.role
          });
          break;
        case 'quiz_push':
          await window.EventBus.emit('quiz:push_question', {
            questionIds: action.questionIds
          });
          break;
        // ... 其他动作
      }
      // 动作之间留 200ms 间隔，便于观察
      await new Promise(r => setTimeout(r, 200));
    } catch (err) {
      console.error(`Action execution failed: ${action.type}`, err);
      // 失败降级：继续执行下一个动作

  }
```

```javascript
// js/stress-engine.js（新模块）
function calculateStressIndex(userStats, moodLogs, days = 7) {
  const now = Date.now();
  const since = now - days * 24 * 60 * 60 * 1000;
  
  // 因子 1: 学习强度（近 N 日平均日学习时长）
  const recentSessions = userStats.focusSessions.filter(s => 
    new Date(s.started_at).getTime() > since
  );
  const avgDailyMinutes = recentSessions.reduce((sum, s) => sum + s.duration, 0) / days;
  const studyIntensity = Math.min(avgDailyMinutes / 360, 1);  // 0-6h 映射 0-1
  
  // 因子 2: 正确率波动（近 N 日标准差）
  const dailyAccuracies = Object.entries(userStats.dailyStats)
    .filter(([date]) => new Date(date).getTime() > since)
    .map(([_, stats]) => stats.correct / stats.total)
    .filter(acc => !isNaN(acc));
  const meanAcc = dailyAccuracies.reduce((a, b) => a + b, 0) / dailyAccuracies.length;
  const variance = dailyAccuracies.reduce((sum, acc) => sum + Math.pow(acc - meanAcc, 2), 0) / dailyAccuracies.length;
  const accuracyVolatility = Math.min(Math.sqrt(variance) / 0.3, 1);
  
  // 因子 3: 番茄完成率
  const plannedPomodoros = userStats.pomodoroPlanned || 1;
  const completedPomodoros = userStats.pomodoroCompleted || 0;
  const pomodoroCompletionRate = 1 - Math.min(completedPomodoros / plannedPomodoros, 1);
  
  // 因子 4: 情绪低落频率
  const recentMoods = moodLogs.filter(m => new Date(m.created_at).getTime() > since);
  const lowMoodCount = recentMoods.filter(m => m.mood_level <= 2).length;
  const lowMoodFrequency = Math.min(lowMoodCount / (days * 2), 1);  // 每天最多 2 次
  
  // 因子 5: 睡眠规律性（可选，默认 0.5）
  const sleepIrregularity = userStats.sleepIrregularity ?? 0.5;
  
  // 加权求和
  const weights = {
    studyIntensity: 0.20,
    accuracyVolatility: 0.25,
    pomodoroCompletionRate: 0.15,
    lowMoodFrequency: 0.30,
    sleepIrregularity: 0.10
  };
  
  const factors = {
    studyIntensity,
    accuracyVolatility,
    pomodoroCompletionRate,
    lowMoodFrequency,
    sleepIrregularity
  };
  
  const stressIndex = Object.entries(factors)
    .reduce((sum, [key, value]) => sum + value * weights[key], 0);
  
  // 识别主要因素
  const mainFactor = Object.entries(factors)
    .map(([key, value]) => ({ key, value, weighted: value * weights[key] }))
    .sort((a, b) => b.weighted - a.weighted)[0];
  
  const factorLabels = {
    studyIntensity: '学习强度过高',
    accuracyVolatility: '正确率波动较大',
    pomodoroCompletionRate: '番茄完成率低',
    lowMoodFrequency: '情绪低落频繁',
    sleepIrregularity: '睡眠不规律'
  };
  
  const level = stressIndex < 0.3 ? 'low' : stressIndex < 0.6 ? 'moderate' : 'high';
  
  return {
    score: Math.round(stressIndex * 100),
    level,
    mainFactor: factorLabels[mainFactor.key],
    factors,
    recommendation: getStressRecommendation(stressIndex, mainFactor.key, level)
  };
}

function getStressRecommendation(stressIndex, mainFactor, level) {
  const recommendations = {
    studyIntensity: '建议减少每日学习时长，增加休息频次。',
    accuracyVolatility: '可能是疲劳导致，建议今天做轻量卡片复习。',
    pomodoroCompletionRate: '番茄完成率低可能说明任务过难，建议拆分小任务。',
    lowMoodFrequency: '情绪低落频繁，建议与信任的人聊聊，或拨打 12320 热线。',
    sleepIrregularity: '睡眠不规律影响学习，建议固定就寝时间。'
  };
  
  if (level === 'high') {
    return `⚠️ 你的学习压力较高。${recommendations[mainFactor]} 如果持续感到压力，请寻求专业帮助。`;
  } else if (level === 'moderate') {

  } else {
    return `✅ 你的学习压力较低，保持当前节奏即可。`;
  }
}
```

```javascript
const DNA_BASES = {
  A: { color: '#4a7c59', label: '细胞生物学' },
  T: { color: '#c4956a', label: '遗传学' },
  G: { color: '#1a3a2a', label: '生态学' },

function generateLearningDNA(userStats) {
  const modules = ['cellular', 'genetics', 'ecology', 'biochem'];
  const bases = ['A', 'T', 'G', 'C'];
  const sequence = [];
  const breakdown = {};
  
  // 计算每个模块的掌握度
  modules.forEach((module, idx) => {
    const moduleStats = userStats.moduleStats?.[module] || { mastery: 0 };
    const mastery = Math.max(0, Math.min(1, moduleStats.mastery));
    breakdown[module] = mastery;
  });
  
  // 生成 32 位序列（每 4 位一轮，每位对应一个模块）
  for (let i = 0; i < 32; i++) {
    const moduleIdx = i % 4;
    const module = modules[moduleIdx];
    const mastery = breakdown[module];
    const base = bases[moduleIdx];
    
    sequence.push({
      position: i,
      base,
      module,
      mastery,
      brightness: 0.3 + mastery * 0.7  // 0.3-1.0
    });
  }
  
  // 计算完整度
  const completeness = Object.values(breakdown)
    .reduce((sum, m) => sum + m, 0) / 4;
  
  // 识别最弱与最强
  const sortedModules = Object.entries(breakdown)
    .sort(([, a], [, b]) => b - a);
  const strongest = sortedModules[0];
  const weakest = sortedModules[sortedModules.length - 1];
  
  return {
    sequence,
    completeness,
    breakdown,
    strongest: { module: strongest[0], mastery: strongest[1] },
    weakest: { module: weakest[0], mastery: weakest[1] }
  };
}
```

```javascript
        break;
      case 'animation':
        await this.playAnimationScene(scene);
        break;
      case 'discussion':
        await this.playDiscussionScene(scene);
        break;
      case 'quiz':
        await this.playQuizScene(scene);
        break;
    }

    if (this.isPlaying) {
      await this.nextScene();
    }

    this.displayTeacherText(text);
    
    // TTS 朗读
    if (this.ttsEngine.isSupported()) {
      this.ttsEngine.speak(text, 'teacher');
    }
    
    // 执行动作
    await executeActions(actions);
    
    // 等待讲稿完成
    await this.waitForDuration(scene.duration_seconds);
  }

    // 加载动画
    await window.EventBus.emit('bio-animation:load', {
      animationId: scene.animation_id
    });
    
    // 生成讲稿
    const script = await this.generateTeacherScript(scene);
    const { text, actions } = parseTeacherOutput(script);
    
    // TTS 朗读 + 动作执行
    this.displayTeacherText(text);
    if (this.ttsEngine.isSupported()) {
      this.ttsEngine.speak(text, 'teacher');
    }
    await executeActions(actions);
    
    await this.waitForDuration(scene.duration_seconds);
  }

    const discussion = await generateDiscussion(

    );
```

# 附录 A：技术选型报告（详细版）

> 本附录阐明 BioQuest v4.0 每一项技术决策的备选方案、对比依据与最终选择理由，确保零成本、大陆可访问、纯前端三大硬约束被严格遵守。

## A.1 前端框架选型

### A.1.1 备选方案

| 方案 | 优点 | 缺点 | 大陆可访问 | 零成本 |
|------|------|------|-----------|--------|
| **原生 HTML/CSS/JS（现状）** | 无构建、无依赖、学习曲线低、CDN 友好 | 缺乏组件化、状态管理需手写 | ✅ | ✅ |
| React + Vite | 组件化强、生态丰富 | 需构建步骤、JSX 学习成本 | ✅（CDN）| ✅ |
| Vue 3 + Vite | 渐进式、文档中文友好 | 需构建步骤 | ✅ | ✅ |
| Svelte | 编译时优化、bundle 小 | 生态较小 | ✅ | ✅ |
| SolidJS | 性能极佳 | 生态最小 | ✅ | ✅ |
| Astro | 内容站点友好 | SPA 体验弱 | ✅ | ✅ |

### A.1.2 最终选择：原生 HTML/CSS/JS + 模块化 JS

**决策理由**：
1. **初赛已用此栈**：48 个 JS 文件已就绪，迁移成本远高于收益
2. **零构建部署**：GitHub Pages 直接 push 即上线，无 CI/CD 复杂度
3. **TRAE Solo Agent 友好**：TRAE 对原生 JS 的代码生成质量高于 React（基于实测）
4. **大陆访问稳定**：不依赖 npm registry，CDN 用 jsdelivr 国内镜像
5. **复赛后可迁移**：若需引入框架，可逐页迁移（先迁移最复杂的 dashboard）

**风险与缓解**：
- 风险：状态管理混乱 → 缓解：复赛统一用 EventBus + CustomEvent 解耦
- 风险：组件复用低 → 缓解：抽取 `components/` 目录，用 Web Components 封装高频组件

### A.1.3 何时考虑迁移到框架

- 单文件超过 5000 行 → 已触发（app.js 108K、admin.js 182K）
- 同一组件在 3+ 页面重复实现 → 已触发（弹窗、卡片）
- 团队成员 ≥ 2 人且不熟悉原生 JS → 未触发

**结论**：复赛坚守原生栈，决赛后视情况迁移到 Vue 3（中文文档友好）。

1. **大陆访问稳定**：Cloudflare 全球 CDN，大陆节点覆盖好
2. **零成本**：无限免费静态托管
3. **HTTPS 自动签发**：无需手动配置证书
4. **自定义域名**：bio.dada.im 已配置
5. **git push 即部署**：连接 GitHub 仓库自动构建

## A.5 关键算法选型

### A.5.1 间隔重复算法

| 算法 | 复杂度 | 效果 | 实现 | 选择 |
|------|--------|------|------|------|
| **FSRS-4.5** | 中 | 业界 SOTA | ts/js 版本可用 | ✅ 已选 |
| SM-2 | 低 | Anki 经典 | 易实现 | ❌ 已弃用 |
| Leitner | 极低 | 一般 | 最简单 | ❌ |
| Half-Life Regression | 高 | 较好 | 需训练 | ❌ |

**决策**：坚守 FSRS-4.5，复赛 P0 任务就是修复初赛未加载的 bug。

### A.5.2 知识追踪算法

| 算法 | 复杂度 | 输出 | 实现 | 选择 |
|------|--------|------|------|------|
| **BKT** | 低 | 二值掌握度 | 已实现 | ✅ 已选 |
| IRT | 中 | 能力值 θ | 已实现 | ✅ 配合 |
| DKT | 高 | 概率分布 | 需 TensorFlow.js | ❌ 太重 |
| AKT | 极高 | 注意力权重 | 需训练 | ❌ |

**决策**：BKT + IRT 双引擎，DKT 留待决赛后探索。

### A.5.3 OCR 引擎

| 方案 | 大陆可访问 | 准确率 | 成本 | 选择 |
|------|-----------|--------|------|------|
| **Tesseract.js WASM** | ✅ 客户端 | 中 | 零 | ✅ 兜底 |
| **GLM-4V 视觉模型** | ✅ | 高 | 用户 Key | ✅ 优先 |
| Google Cloud Vision | ❌ 需翻墙 | 极高 | 付费 | ❌ |
| 百度 OCR API | ✅ | 高 | 免费有限 | ❌ 需后端 |

**决策**：双引擎架构保留，视觉模型优先 + Tesseract 兜底。

```javascript
/**
 * BioQuest AI 课堂事件总线
 * 职责：解析 LLM 输出中的 [ACTION:type:param] 标签，分发到对应 UI 控制器
 * 设计原则：宽容解析 + 文本兜底（LLM 输出格式不稳定时的降级）
 */
(function (global) {
  'use strict';

  // ACTION 类型注册表：type → handler 函数
  const ACTION_REGISTRY = {
    highlight: handleHighlight,     // 高亮 DOM 元素
    lightup: handleLightup,         // 点亮知识图谱节点
    draw: handleDraw,               // 白板画图
    tts: handleTTS,                 // 语音朗读
    play: handlePlay,               // 播放 Canvas 动画
    pause: handlePause,             // 暂停动画
    seek: handleSeek,               // 跳转动画帧
    quiz: handleQuiz,               // 触发小测
    discuss: handleDiscuss,         // 触发多智能体讨论
    wait: handleWait                // 等待用户点击继续
  };

  // ACTION 标签正则：[ACTION:type:param]
  // param 可包含除 ] 外的任意字符（含中文、空格、JSON）
  const ACTION_REGEX = /\[ACTION:(\w+):([^\]]+)\]/g;

  /**
   * 解析 LLM 输出，分离纯文本与 ACTION 标签
   * @param {string} raw - LLM 原始输出
   * @returns {Array} 段落数组：{type: 'text'|'action', payload}
   */
  function parseStream(raw) {
    const segments = [];
    let lastIndex = 0;
    let match;

    ACTION_REGEX.lastIndex = 0;
    while ((match = ACTION_REGEX.exec(raw)) !== null) {
      // 标签前的纯文本
      if (match.index > lastIndex) {
        segments.push({
          type: 'text',
          payload: raw.slice(lastIndex, match.index)
        });
      }
      // ACTION 标签
      const [, actionType, rawParam] = match;
      segments.push({
        type: 'action',
        payload: { type: actionType, param: rawParam.trim() }
      });
      lastIndex = match.index + match[0].length;
    }

    // 末尾剩余文本
    if (lastIndex < raw.length) {
      segments.push({
        type: 'text',
        payload: raw.slice(lastIndex)
      });
    }

    return segments;
  }

  /**
   * 按顺序执行段落数组：文本渲染到对话框，ACTION 调用 handler
   * @param {Array} segments - parseStream 返回值
   * @param {Object} ctx - 课堂上下文（DOM 引用、状态等）
   */
  async function executeSegments(segments, ctx) {
    for (const seg of segments) {
      if (seg.type === 'text') {
        await ctx.renderText(seg.payload);
      } else {
        const handler = ACTION_REGISTRY[seg.payload.type];
        if (handler) {
          try {
            await handler(seg.payload.param, ctx);
          } catch (err) {
            console.warn(`[EventBus] ACTION ${seg.payload.type} failed:`, err);
            // 失败降级：将 ACTION 标签作为纯文本显示
            await ctx.renderText(`[${seg.payload.type}: ${seg.payload.param}]`);
          }
        } else {
          console.warn(`[EventBus] unknown ACTION type: ${seg.payload.type}`);
          await ctx.renderText(seg.payload.param);
        }
      }
    }
  }

  // ===== Handler 实现 =====

  async function handleHighlight(selector, ctx) {
    const el = document.querySelector(selector);
    if (!el) {
      console.warn(`[highlight] element not found: ${selector}`);
      return;
    }
    el.classList.add('bq-classroom-highlight');
    el.scrollIntoView({ behavior: 'smooth', block: 'center' });
    await wait(2500);
    el.classList.remove('bq-classroom-highlight');
  }

  async function handleLightup(nodeId, ctx) {
    if (!global.KnowledgeGraph?.lightupNode) {
      console.warn('[lightup] KnowledgeGraph not ready');
      return;
    }
    global.KnowledgeGraph.lightupNode(nodeId);
    await wait(2000);
    global.KnowledgeGraph.dimAll();
  }

  async function handleDraw(instruction, ctx) {
    if (!global.Whiteboard?.draw) return;
    await global.Whiteboard.draw(instruction);
  }

  async function handleTTS(text, ctx) {
    if (!('speechSynthesis' in global)) {
      // TTS 不可用：降级为文本显示
      await ctx.renderText(`🔊 ${text}`);
      return;
    }
    const utter = new SpeechSynthesisUtterance(text);
    utter.lang = 'zh-CN';
    utter.rate = 0.95;
    return new Promise(resolve => {
      utter.onend = resolve;
      utter.onerror = resolve;
      global.speechSynthesis.speak(utter);
    });
  }

  async function handlePlay(animationId, ctx) {
    if (!global.BioAnimation?.play) return;
    global.BioAnimation.play(animationId);
  }

  async function handlePause(_, ctx) {
    global.BioAnimation?.pause?.();
  }

  async function handleSeek(frameStr, ctx) {
    const frame = parseInt(frameStr, 10);
    if (Number.isFinite(frame)) global.BioAnimation?.seek?.(frame);
  }

  async function handleQuiz(quizSpec, ctx) {
    // quizSpec 格式：'concept=有丝分裂&count=3'
    const params = new URLSearchParams(quizSpec);
    const concept = params.get('concept');
    const count = parseInt(params.get('count') || '3', 10);
    await ctx.triggerQuiz(concept, count);
  }

  async function handleDiscuss(topic, ctx) {
    await ctx.triggerDiscussion(topic);
  }

  async function handleWait(msStr, ctx) {
    const ms = parseInt(msStr, 10) || 1000;
    await wait(ms);
  }

  function wait(ms) {
    return new Promise(r => setTimeout(r, ms));
  }

  // 导出
  global.EventBus = {
    parseStream,
    executeSegments,
    ACTION_REGISTRY
  };
})(window);
```

## C.3 学习 DNA + 情绪 DNA 双画像

### C.3.1 编码逻辑

```javascript
/**
 * learning-dna.js
 * 将 8 模块掌握度编码为 32 字符 ATGC 序列
 * 碱基映射：掌握度 0-0.25 → A，0.25-0.5 → T，0.5-0.75 → G，0.75-1.0 → C
 */
(function (global) {
  'use strict';

  const MODULES = [
    'cell', 'genetics', 'ecology', 'molecule',
    'evolution', 'physiology', 'plant', 'microbe'
  ];

  /**
   * 编码学习 DNA
   * @param {Object} moduleStates - {cell: 0.6, genetics: 0.3, ...}
   * @returns {string} 32 字符 ATGC 序列（8 模块 × 4 位）
   */
  function encodeLearningDNA(moduleStates) {
    let dna = '';
    for (const mod of MODULES) {
      const mastery = moduleStates[mod] ?? 0;
      // 4 位编码：每两位表示整数部分，后两位表示小数部分
      dna += encodeQuartet(mastery);
    }
    return dna;
  }

  function encodeQuartet(value) {
    // 0-1 → 4 个碱基（256 级精度）
    const level = Math.min(255, Math.max(0, Math.floor(value * 255)));
    const b1 = (level >> 6) & 0x3;
    const b2 = (level >> 4) & 0x3;
    const b3 = (level >> 2) & 0x3;
    const b4 = level & 0x3;
    return [b1, b2, b3, b4].map(bitsToBase).join('');
  }

  function bitsToBase(bits) {
    return ['A', 'T', 'G', 'C'][bits];
  }

  function baseToBits(base) {
    return { A: 0, T: 1, G: 2, C: 3 }[base] ?? 0;
  }

  /**
   * 解码学习 DNA → 8 模块掌握度
   */
  function decodeLearningDNA(dna) {
    const states = {};
    for (let i = 0; i < MODULES.length; i++) {
      const quartet = dna.slice(i * 4, i * 4 + 4);
      const b1 = baseToBits(quartet[0]);
      const b2 = baseToBits(quartet[1]);
      const b3 = baseToBits(quartet[2]);
      const b4 = baseToBits(quartet[3]);
      const level = (b1 << 6) | (b2 << 4) | (b3 << 2) | b4;
      states[MODULES[i]] = level / 255;
    }
    return states;
  }

  /**
   * 编码情绪 DNA（7 日窗口）
   * 每日 3 次打卡 → 1 个碱基，7 日共 21 位，补齐到 32 位
   */
  function encodeMoodDNA(moodLog7d) {
    // moodLog7d: [{date, morning, noon, evening}, ...]
    let dna = '';
    for (const day of moodLog7d) {
      // 一日 3 次打卡平均情绪值（0-1，0=最差，1=最好）
      const avg = (day.morning + day.noon + day.evening) / 3;
      dna += encodeQuartet(avg);
    }
    // 补齐 32 位
    while (dna.length < 32) dna += 'A';
    return dna.slice(0, 32);
  }

  /**
   * 计算双 DNA 的"互补度"（学习-情绪相关性）
   * 高互补度：学习好时情绪也好
   * 低互补度：学习好但情绪差（需关注身心健康）
   */
  function computeComplementarity(dna1, dna2) {
    let matches = 0;
    for (let i = 0; i < 32; i++) {
      // 互补配对：A-T, G-C
      const pair = dna1[i] + dna2[i];
      if (pair === 'AT' || pair === 'TA' || pair === 'GC' || pair === 'CG') {
        matches++;
      }
    }
    return matches / 32;
  }

  global.LearningDNA = {
    encodeLearningDNA,
    decodeLearningDNA,
    encodeMoodDNA,
    computeComplementarity,
    MODULES
  };
})(window);
```

```javascript
/**
 * double-helix.js
 * Canvas 2D 绘制双螺旋：学习 DNA（左链）+ 情绪 DNA（右链）
 */
function renderDoubleHelix(canvas, dna1, dna2) {
  const ctx = canvas.getContext('2d');
  const W = canvas.width;
  const H = canvas.height;
  ctx.clearRect(0, 0, W, H);

  const baseColors = {
    A: '#4a7c59', // sage
    T: '#c4956a', // terracotta
    G: '#5b8def', // blue
    C: '#e8b04f'  // amber
  };

  const cx = W / 2;
  const amplitude = W * 0.18;
  const helixHeight = H * 0.9;
  const startY = H * 0.05;
  const steps = 32;

  for (let i = 0; i < steps; i++) {
    const t = i / (steps - 1);
    const y = startY + t * helixHeight;
    const phase = t * Math.PI * 4; // 2 圈
    const x1 = cx + Math.sin(phase) * amplitude;
    const x2 = cx - Math.sin(phase) * amplitude;

    // 碱基对连线（互补配对高亮）
    const isComplement = isPair(dna1[i], dna2[i]);
    ctx.strokeStyle = isComplement ? '#4a7c59' : '#ccc';
    ctx.lineWidth = isComplement ? 3 : 1;
    ctx.beginPath();
    ctx.moveTo(x1, y);
    ctx.lineTo(x2, y);
    ctx.stroke();

    // 左链碱基（学习 DNA）
    ctx.fillStyle = baseColors[dna1[i]] || '#999';
    ctx.beginPath();
    ctx.arc(x1, y, 8, 0, Math.PI * 2);
    ctx.fill();

    // 右链碱基（情绪 DNA）
    ctx.fillStyle = baseColors[dna2[i]] || '#999';
    ctx.beginPath();
    ctx.arc(x2, y, 8, 0, Math.PI * 2);
    ctx.fill();
  }

  // 骨架（两条波浪线）
  ctx.strokeStyle = 'rgba(74, 124, 89, 0.3)';
  ctx.lineWidth = 2;
  for (let side of [1, -1]) {
    ctx.beginPath();
    for (let i = 0; i <= 100; i++) {
      const t = i / 100;
      const y = startY + t * helixHeight;
      const phase = t * Math.PI * 4;
      const x = cx + side * Math.sin(phase) * amplitude;
      if (i === 0) ctx.moveTo(x, y);
      else ctx.lineTo(x, y);
    }
    ctx.stroke();
  }
}

function isPair(b1, b2) {
  return (b1 + b2) === 'AT' || (b1 + b2) === 'TA' ||
         (b1 + b2) === 'GC' || (b1 + b2) === 'CG';
}
```

## C.5 FSRS-4.5 调度（修复 P0-1）

```javascript
/**
 * fsrs-bridge.js
 * 桥接 FSRS-4.5 算法到 BioQuest 数据层
 * 修复 P0-1：初赛 FSRS 未加载的 bug
 */
(function (global) {
  'use strict';

  let fsrsInstance = null;

  /**
   * 初始化 FSRS（必须在 index.html 同步加载 fsrs-algorithm.js 后调用）
   */
  function init() {
    if (typeof global.FSRS === 'undefined') {
      console.error('[FSRS] fsrs-algorithm.js not loaded! Falling back is FORBIDDEN in v4.0.');
      throw new Error('FSRS not loaded');
    }
    fsrsInstance = new global.FSRS({
      enable_fuzzing: true,
      request_retention: 0.9,
      maximum_interval: 365
    });
    console.info('[FSRS] initialized:', !!fsrsInstance);
  }

  /**
   * 评分后调度下次复习
   * @param {Object} card - FSRS card 状态
   * @param {number} rating - 1=again, 2=hard, 3=good, 4=easy
   * @returns {Object} { card, review_time, next_review }
   */
  function schedule(card, rating) {
    if (!fsrsInstance) init();

    const now = new Date();
    const result = fsrsInstance.repeat(card, now);
    const updated = result[rating];

    return {
      card: updated.card,
      review_time: now,
      next_review: updated.card.due
    };
  }

  /**
   * 创建新卡
   */
  function createNewCard() {
    if (!fsrsInstance) init();
    return fsrsInstance.createEmptyCard();
  }

  /**
   * 持久化到 Supabase cards_progress 表
   */
  async function persist(userId, cardId, fsrsState, due) {
    await SupabaseClient.from('cards_progress').upsert({
      user_id: userId,
      card_id: cardId,
      fsrs_state: fsrsState,
      due: due.toISOString(),
      last_review: new Date().toISOString()
    });
  }

  global.FSRSBridge = { init, schedule, createNewCard, persist };
})(window);
```

# 附录 D：苛刻批评者视角 - 风险评估与改进建议

> 本附录以最苛刻的批评者视角审视 BioQuest v4.0 方案，识别潜在漏洞、幻觉承诺、设计与实现脱节之处，并提出尖锐改进建议。这不是自我吹捧，而是参赛前必须正视的真问题。

## D.1 对方案本身的根本性质疑

### D.1.1 「4 大深化模块」真的深化了吗？

**质疑**：4 个模块（AI 课堂 / 苏格拉底同学 / 双 DNA / 身心健康）看似创新，但每个都停留在 POC 级别，深度不足以撑起「复赛晋级」的分量。

**证据**：
- AI 课堂的 `[ACTION:...]` 标签解析是简单正则，OpenMAIC 已有更成熟的 multi-agent 协议
- 苏格拉底 4 级提示本质是 4 个不同 system prompt，没有真正的"苏格拉底对话"能力
- 双 DNA 编码只是把 0-1 数值映射到 ATGC，没有真正的"基因表达"逻辑
- 情绪打卡 + 压力指数是 30 行代码的玩具算法，无法真正反映心理状态

**改进建议**：
1. 至少 1 个模块做"深井"：选择 AI 课堂，做到能生成连续 3-5 节有上下文关联的课程（不是孤立单节）
2. 苏格拉底同学引入"对话历史感知"：根据学生前几轮的回答调整 L2/L3 提示内容
3. 双 DNA 增加"突变"机制：长期低掌握度模块的碱基对有概率"突变"，触发 AI 主动干预
4. 压力指数算法公开权重，邀请 1-2 名心理学背景用户 review

### D.1.2 「纯前端 + Supabase」是否名不副实？

**质疑**：Supabase 本质是后端服务（PostgreSQL + Auth + Storage + Realtime），把它叫做「纯前端」是偷换概念。

**证据**：
- RLS 策略写在 SQL 里，是后端逻辑
- Auth 流程依赖 Supabase 服务器
- Realtime 订阅走 Supabase WebSocket

**反驳与改进**：
- 严格定义：「纯前端」=「无需自建后端运行时」，Supabase 作为 BaaS 不算自建
- 在 README 与社区帖中明确表述：「纯前端 SPA + Supabase BaaS」，避免误导评审
- 复赛评审可能来自前端背景，对「纯前端」理解严格，需提前准备话术

### D.1.3 「零成本」承诺的脆弱性

**质疑**：依赖 6 家 LLM 免费额度 + Supabase 免费层 + Cloudflare 免费层，任何一家调整政策都会破坏承诺。

**具体风险点**：
- DeepSeek 2024 年曾临时下调免费额度，复赛期若发生类似调整，AI 课堂将无法演示
- Supabase 免费层有 50000 MAU 上限，若初赛帖子引流爆发，可能触顶
- Cloudflare Pages 大陆访问质量受运营商影响，可能突然变差

**改进建议**：
1. 准备至少 2 套演示用 LLM Key（用户自配 + 开发者备用），避免现场失灵
2. 监控 Supabase MAU 接近 80% 时，主动发邮件给用户引导自配 Key
3. 准备 GitHub Pages 镜像作为 Cloudflare 的 fallback，DNS 可一键切换
4. 在社区帖中诚实声明：「零成本依赖免费层服务，如服务调整可能影响可用性」

## D.2 技术架构的潜在漏洞

### D.2.1 事件总线的 LLM 输出不稳定问题

**质疑**：`[ACTION:type:param]` 标签完全依赖 LLM 生成，但实测各家 LLM 对格式指令的遵守度差异巨大。

**已知失败模式**：
- DeepSeek 偶尔会把标签写在 ``` 代码块里，导致正则无法匹配
- 智谱 GLM 有时会生成 `[ACTION:tts: "你好"]`（带引号），导致 param 解析错误
- Kimi 偶尔会"自由发挥"创造 `[ACTION:answer:...]` 这种未注册的 type

**改进建议**：
1. 在 system prompt 中给出 5+ 个 few-shot 示例，覆盖典型场景
2. 解析时宽容处理：去除多余引号、空白、代码块标记
3. 未注册 type 不报错，降级为纯文本显示
4. 增加 `validateActionScript()` 函数，在执行前预检脚本合理性（如至少 1 个 ACTION、无重复 5 次以上同类 ACTION）
5. 实测 6 家 LLM 各生成 10 节课脚本，统计格式遵守率，选 top 3 作为默认

### D.2.2 双 DNA Canvas 渲染的性能问题

**质疑**：32 个碱基对 + 骨架 + 高亮，看似简单，但在低端移动设备上可能掉帧。

**实测预期**：
- iPhone 12+：流畅 60fps
- 中端安卓（红米 Note 系列）：可能 30-40fps
- 低端安卓（< 2GB RAM）：可能卡顿

**改进建议**：
1. 使用 `requestAnimationFrame` 而非 `setInterval`
2. 不可见时（Intersection Observer）暂停渲染
3. 移动端降级为静态 SVG（不做螺旋旋转动画）
4. 限制 DPR ≤ 2，避免高分屏过载

### D.2.3 Supabase RLS 配置错误的灾难性后果

**质疑**：RLS 是数据安全的最后一道防线，但 SQL 配置易错，初赛期是否真的 review 过？

**典型错误模式**：
- 忘记 `enable row level security`，导致表默认公开
- `using (true)` 写成 `with check (true)`，导致可读但不可写或反之
- 外键关联表的级联策略不当，删除用户后数据残留

**改进建议**：
1. 用 `pg_dump --schema-only` 导出 schema，对照 RLS 清单逐表 review
2. 写 SQL 测试用例：模拟用户 A 尝试读取用户 B 的数据，应返回空
3. 用 Supabase Dashboard 的 SQL Editor 跑渗透测试
4. 复赛前邀请 1 位有 Supabase 经验的朋友做安全 review

### D.2.4 危机干预的法律与伦理风险

**质疑**：情绪打卡 + 危机词检测听起来很美，但实际可能造成更大伤害。

**具体风险**：
- 误判：用户写"我今天累得想消失"，被识别为危机，弹窗反而打扰
- 漏判：用户用隐喻表达自杀意念（如"想去一个很远的地方"），未被识别
- 责任：若用户在 BioQuest 留下危机线索后真的出事，产品是否担责？

**改进建议**：
1. 危机词库严格限定为"明确意图表达"（如"想自杀"），不含模糊表述
2. 资源卡片显式声明「BioQuest 不构成医疗建议，紧急情况请拨 120」
3. 不存储危机词触发的原始文本，只存储触发时间戳（减少数据泄露风险）
4. 在 README 与社区帖中明确「本产品不提供心理医疗服务」
5. 建议在隐私政策中说明数据用途，征得用户（或监护人）同意

## D.3 产品定位的盲点

### D.3.1 目标用户过宽

**质疑**：方案声称面向「竞赛生 + 高考学生 + 自学者 + 教师」四类用户，但 20 天不可能同时满足四类。

**证据**：
- 竞赛生需要联赛真题（高难度、超纲）
- 高考学生需要课标对齐（中难度、严格按教材）
- 自学者需要兴趣引导（趣味性、低门槛）
- 教师需要班级管理（数据、批改、协作）

**改进建议**：
1. 复赛聚焦 1 类核心用户：**高中生物竞赛生**（初赛已服务，复赛加深）
2. 其他 3 类用户在 README 中标注「未来支持」
3. UI 文案、题目难度、AI 课堂脚本风格均围绕竞赛生调整
4. 评审看到聚焦的用户画像，比看到「四类用户都服务」更有说服力

### D.3.2 与初赛的关系处理

**质疑**：复赛方案在初赛基础上「优化」，但没说清是「推翻初赛」还是「延续初赛」。

**风险**：
- 评审可能误以为复赛只是初赛 demo 的修补，没看到创新
- 也可能误以为复赛推翻了初赛定位，导致初赛成果被否定

**改进建议**：
1. 在社区帖第 0 节明确：「复赛在初赛 BioQuest 基础上深化升级，初赛的 13 个核心模块全部保留并修复 P0 问题，新增 4 大深化模块」
2. 在演示视频开头 10 秒做"初赛回顾 + 复赛新增"的对比
3. GitHub README 顶部加一个"v3.1 → v4.0 演进图"

### D.3.3 与 OpenMAIC 的差异化不足

**质疑**：AI 课堂借鉴 OpenMAIC，但纯前端实现必然功能弱于原版（无多智能体协作、无复杂课堂场景）。

**证据**：
- OpenMAIC 是清华大学的研究系统，有多智能体协作、知识图谱推理、课堂状态机
- BioQuest 的 AI 课堂只是单 LLM 生成脚本 + 标签解析，本质是"披着课堂外衣的对话机器人"

**改进建议**：
1. 明确差异化定位：「OpenMAIC 是研究系统，BioQuest 是面向高中生的产品化应用」
2. 借鉴 OpenMAIC 的"事件总线"思想，但简化为高中生能理解的 4 类 ACTION
3. 在社区帖中诚实声明：「借鉴 OpenMAIC 思想，纯前端实现简化版，聚焦产品化落地」
4. 不与 OpenMAIC 直接对比功能丰富度，而是对比"可用性、可访问性、可推广性"

## D.4 文档与表达的潜在问题

### D.4.1 「数万字」是否真的有信息密度？

**质疑**：用户要求"数万字"，但字数不等于信息密度。如果文档充斥重复表述、空泛承诺、格式水分，反而暴露思路不清。

**自查清单**：
- 表格是否每行都有独特信息？还是有重复行？
- 是否每段都有具体数字、案例、引用？还是空泛形容词？
- 附录是否补充了正文未尽的细节？还是复述了同样内容？

**改进建议**：
1. 通读全文，删除每段第一个空泛形容词（如"全面"、"深入"、"创新"）
2. 表格合并重复行，确保每行有差异化信息
3. 每个承诺必须配一个可验证的证据（数字、文件路径、代码片段）
4. 在每个章节末尾加一行「验证方式：xxx」，明确如何证明此节内容真实

### D.4.2 POC 代码是否真的可运行？

**质疑**：附录 C 的代码片段看着完整，但实际跑起来可能有依赖缺失、API 不一致、命名冲突等问题。

**已知问题**：
- `AiClient.chatStream` 在现有 ai-client.js 中是否真的存在？签名是否一致？
- `ClassmateUI`、`ClassroomUI` 在代码中被引用但未定义
- `SupabaseClient.from().insert()` 是否真的 work？

**改进建议**：
1. 在 D16-D17 把每个 POC 代码片段单独抽成 HTML 文件跑一遍
2. 跑不通的标注「概念验证，需调整」而非"可直接运行"
3. 在附录 C 顶部声明：「本附录代码为 POC 级别，部分依赖（如 ClassmateUI）需配合主仓库 UI 上下文」
4. 把 POC 代码也 push 到 `poc/` 目录，让评审可点击查看

### D.4.3 时间线的乐观偏差

**质疑**：20 天 230 小时 = 日均 11.5 小时，这是高估个人产能的典型偏差。

**典型乐观偏差**：
- D2 FSRS 修复预估 8h，实际可能因依赖问题变 16h
- D5-D10 模块开发预估 10h/天，实际前 2 天因不熟悉可能 14h 才完成
- D12 题库生成 170 题，每题需 review，实际可能花 12h 而非 8h

**改进建议**：
1. 给每个任务加 30% buffer：8h 任务按 10.4h 规划
2. 用"三点估算"：乐观 O、最可能 M、悲观 P，期望 = (O + 4M + P) / 6
3. 每天记录实际工时，D5、D10、D15 三次校正剩余计划
4. 若 D11 M2 未达标，立即触发 Plan B（砍 L3/L4 级、改静态 SVG）

## D.5 评审视角的盲点

### D.5.1 评审可能不是前端背景

**质疑**：评审可能来自产品、设计、教育、AI 等不同背景，对"纯前端 + Supabase + 多 LLM 路由"的技术难度感知不同。

**风险**：
- 后端背景评审可能觉得 Supabase 太简单，不够"硬核"
- 设计背景评审可能关注视觉一致性，忽略技术深度
- 教育背景评审可能关注教学效果，质疑 AI 课堂是否真的有效

**改进建议**：
1. 演示视频前 30 秒用一句话讲清技术栈：「纯前端 + Supabase + 6 家 LLM 多路由，零成本部署」
2. 社区帖用 1 段话讲教学效果：「AI 课堂 5-8 分钟一节，覆盖讲解/动画/讨论/小测 4 场景，模拟真实课堂节奏」
3. 视觉走查确保任何背景的评审都觉得"看起来专业"
4. 准备 3 套话术：技术向、产品向、教育向，根据评审问题切换

### D.5.2 评审时间有限

**质疑**：复赛 20 进 8，评审可能每项目只看 5-10 分钟，重点不突出会被淹没。

**改进建议**：
1. 演示视频前 10 秒必须展示最惊艳的画面（AI 老师操作 UI 讲课）
2. 社区帖前 200 字必须讲清新增的 4 大模块与差异化
3. README 顶部一个表格列「v4.0 新增 vs 初赛」
4. GitHub 仓库首页配 demo gif，1 秒内吸引注意

### D.5.3 与其他参赛作品的横向对比

**质疑**：复赛 20 强，BioQuest 不是唯一教育类项目，也不是唯一用 AI 的项目。

**预期竞争对手**：
- 教育 AI 类：可能有更深的学科覆盖（数学/物理/化学）
- 创意工具类：可能有更炫的交互（3D/WebXR/语音）
- 效率工具类：可能有更广的用户场景

**改进建议**：
1. 不与其他项目正面对比功能丰富度
2. 强化「生物 + 教育公平 + 身心健康」三位一体的差异化定位
3. 突出「初赛已上线，复赛是真实迭代」的可信度优势
4. 在社区帖中讲清「为什么是生物、为什么是高中生、为什么是身心健康」

## D.6 最坏情况预案

### D.6.1 复赛提交前夜 Demo 跑不起来

**场景**：D19 晚发现 AI 课堂在 Safari 上完全不工作（事件总线解析失败）。

**应对**：
1. 准备 Chrome 录屏作为 demo 视频（不依赖现场跑）
2. 社区帖附 GitHub 仓库链接，评审可自行 clone 跑
3. 在社区帖诚实声明「Safari 兼容性待修复，建议 Chrome 体验」
4. 立即定位 Safari 问题（可能是 SpeechSynthesis API 差异），D20 早上紧急修

### D.6.2 评审质疑「为什么用原生 JS 不用框架」

**应对话术**：
「初赛时我是高一学生零基础，TRAE Solo Agent 对原生 JS 的代码生成质量最高。复赛期我评估了迁移到 React/Vue 的成本，发现 48 个 JS 文件迁移成本高于收益。我选择坚守原生栈，但通过 EventBus + Web Components 模式弥补组件化不足。决赛后视情况迁移到 Vue 3。」

### D.6.3 评审质疑「身心健康只是噱头」

**应对话术**：
「身心健康不是后期贴上去的功能，而是嵌入学习闭环的设计。具体证据：① 情绪打卡数据影响学习 DNA 双螺旋渲染；② 高压力时自动降低推荐题量；③ 危机词检测命中后弹出资源卡片；④ 苏格拉底同学检测到负面情绪时切换共情模式。每个功能都有代码实现，欢迎查看 GitHub。」

### D.6.4 评审质疑「为什么不直接做后端」

**应对话术**：
「纯前端 + Supabase 是经过深思熟虑的架构决策，原因有三：① 零成本部署，乡村学生也能用；② 无后端运行时，降低维护复杂度，高中生能持续维护；③ 用户自配 LLM Key，转嫁 AI 成本，符合教育公益定位。后端能力通过 Supabase RLS + PostgreSQL + Realtime 已经满足需求。」

## D.8 最终自省

作为最苛刻的批评者，我对 BioQuest v4.0 的最终评价是：

**这不是一个完美的方案，但这是一个诚实的方案。**

它没有用华丽辞藻掩盖初赛的缺陷，没有用 PRD 装腔作势假装实现已就绪，没有用"零成本"承诺逃避技术债。它承认 4 大深化模块都是 POC 级别，承认时间线紧张，承认与 OpenMAIC 的差距，承认评审可能不买账。

**复赛的目标不是赢，是让评审看到一个高中生如何用 TRAE 把"诚实地做产品"这件事做到极致。**

如果连"诚实"都做不到，再多创新点都是空中楼阁。

## E.1 设计哲学

BioQuest 视觉设计的核心是「**学术 + 温度**」：
- **学术**：知识感、严谨感、信任感（深绿、衬线字体、留白）
- **温度**：陪伴感、鼓励感、人文感（暖色点缀、圆润圆角、手写字体）

v4.0 新增模块的视觉设计必须在「学术 + 温度」基础上，体现「**AI 共学**」的新特质：
- AI 不是冰冷的工具，而是有温度的伙伴
- 数据可视化要有美感，不能是冷冰冰的图表
- 危机干预卡片要温暖，不能像医疗告知书
