## 一、苛刻评审诊断（当前版本评分）

以**决赛级评委**的极度苛刻标准，对当前版本逐项打分：

| 维度 | 权重 | 当前得分 | 满分 | 核心问题 |
|------|------|---------|------|----------|
| **产品完成度** | 30% | **45/100** | 100 | 功能堆砌但闭环断裂；无登录状态下核心功能（模考/练习/错题）卡在loading；Supabase依赖导致评审打开即用的体验失效；P0级Bug多 |
| **创新性/解决思路** | 25% | **70/100** | 100 | 功能覆盖面广是优势，但"大而全"反而稀释了核心记忆点；AI课堂/OpenMAIC是亮点，但隐藏太深且依赖Key；社会价值板块停留在文案层面 |
| **技术实现** | 20% | **55/100** | 100 | Supabase是"伪纯前端"——需要后端服务+配置+网络，违反零成本承诺；脚本加载策略混乱（30+script标签同步defer）；首屏加载过重；数据层多套标准；vendor重复加载 |
| **体验设计/UI** | 15% | **65/100** | 100 | 设计系统有雏形但导航过载（顶部20+入口）；移动端适配不完整；空状态/加载态/错误态设计缺失；交互反馈不一致；动效卡顿风险高 |
| **TRAE实践** | 10% | **?/100** | 100 | 需要补充3+真实Session ID、关键步骤截图、开发故事 |

**总分：57/100** — 有好的底子，但距离"稳进决赛"差距巨大。**最致命的问题是：评委打开链接，在不登录、不配置Supabase的情况下，核心功能无法使用。这是直接淘汰级问题。**

## 二、产品定位（重构）

### 2.1 一句话定位
&gt; **不需要登录、不需要配置、打开就能用的生物竞赛学习神器——所有数据在你本地，AI能力可选增强，零成本零门槛。**

### 2.2 核心铁律（不可违反）
| 铁律 | 说明 |
|------|------|
| **打开即用** | 评审打开链接后3秒内可交互，**不需要登录、不需要注册、不需要配置任何东西** |
| **零后端依赖** | 完全移除Supabase依赖，所有数据存本地（IndexedDB+localStorage），不向任何第三方服务器发请求（除AI直连由用户主动触发） |
| **离线可用** | PWA缓存完整核心功能，断网可正常使用练习/卡片/错题/图谱 |
| **核心功能无门槛** | 练习/模考/卡片/错题/图谱/实验室6大核心模块**不需要API Key**就能完整使用 |
| **AI是增强不是必需** | AI导师/AI课堂等需要LLM的功能标注为"AI增强"，用户可自主选择配置Key，不配置不影响核心体验 |
| **一键部署** | git push到GitHub/Vercel/Netlify即上线，零环境变量配置 |

### 2.3 目标用户与场景（聚焦）

| 用户 | 核心场景 |
|------|---------|
| 竞赛冲刺学生（主） | 刷题→错题→复习→模考 完整闭环 |
| 高中学生（次） | 按章节练习、卡片记忆、动画理解 |
| 好奇探索者（次） | 知识图谱浏览、虚拟实验、分子查看 |

**砍去**：教师模式、社区、排行榜——这些功能依赖后端/社交冷启动，复赛阶段评审体验不到价值，反而增加复杂度。

## 六、技术架构（零成本优化）

### 6.1 脚本加载策略重构

**问题**：当前index.html有30+`<script defer>`标签，全部defer导致首屏解析阻塞，且无法按需加载。

**方案**：

| 资源 | 加载策略 |
|------|---------|
| 核心CSS（globals/layout/header/home） | 同步加载（内联关键CSS更佳） |
| utils.js + fsrs + dexie | 首屏同步（`<script>`非defer，极小体积） |
| 路由模块JS（practice/exam/wrongbook/cards等） | 路由切换时动态`import()`或动态创建script标签 |
| Chart.js/Cytoscape.js/KaTeX | 进入对应模块时动态加载 |
| Three.js/3Dmol/RDKit/igv.js/Tesseract.js | 进入对应模块时动态加载+进度条 |
| GSAP/D3/marked/DOMPurify | 首屏defer（较小） |

### 6.2 首屏性能预算

| 指标 | 预算 |
|------|------|
| 首屏HTML+CSS+核心JS | &lt;150KB gzip |
| LCP（Largest Contentful Paint） | &lt;2.0s |
| TTI（Time to Interactive） | &lt;3.0s |
| CLS（Cumulative Layout Shift） | &lt;0.1 |
| 首屏可交互时间 | &lt;3s |

### 6.3 PWA离线策略

- Core Assets（核心HTML/CSS/JS/首页数据）：Cache First
- 题库JSON/模块JS：Stale While Revalidate
- 图片/字体：Cache First，过期时间7天
- PhET/igv等外部资源：Network First（需要联网）
- 完全离线可用：练习/卡片/错题/图谱/诊断/本地动画 可离线使用
- 离线检测：显示离线指示器，禁用需要联网的功能

### 6.4 代码架构清理

| 任务 | 说明 |
|------|------|
| 删除所有Supabase相关代码 | supabase-client.js/supabase.js/storage.js 全部删除 |
| 删除多套数据层 | 统一走Dexie.js，删除localStorage直接写的业务数据 |
| 拆分超大文件 | app.js按路由拆分为router.js/auth-modal.js等；每个模块一个文件 |
| 删除死代码 | _generateLocalLeaderboard等所有死代码清除 |
| CSS外移 | 所有JS内联CSS注入移到css/对应文件 |
| vendor重复检查 | openmaic下重复的openmaic-json-repair.js等去重 |
