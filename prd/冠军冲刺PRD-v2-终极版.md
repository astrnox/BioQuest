## 零、v1→v2 升级逻辑：从"满分"到"冠军"的认知跃迁

v1解决了"能不能用、会不会被淘汰"的问题；v2要解决的是"评委凭什么给你第一"的问题。

**决赛评委的潜意识打分逻辑（v2必须击中）：**

| 评委内心OS | 权重 | v1是否满足 | v2如何做 |
|-----------|------|-----------|---------|
| "这东西和市面上的有啥不一样？" | 25% | ❌ 功能全但记忆点模糊 | ✅ 打造"Wow Moment"——3个让人记住的独家功能 |
| "纯前端能做到这个？有点东西" | 20% | ⚠️ 技术实现合格但不炫 | ✅ 加入"前端黑科技"展示时刻 |
| "这小孩/团队真的用TRAE做的？" | 15% | ❓ TRAE实践部分空 | ✅ 设计一个完整的TRAE开发故事线 |
| "有点感动/有点意思" | 15% | ❌ 缺乏情感共鸣 | ✅ 加入"温度设计"和社会价值落地 |
| "演示完我想自己试试" | 15% | ⚠️ 体验达标但不勾人 | ✅ Onboarding+即时反馈+心流设计 |
| "代码写得怎么样？" | 10% | ❌ 架构债多 | ✅ 架构重构+可展示的代码质量 |

**v2的三个战略级目标：**
1. **3秒抓眼**：首页Wow Moment（纯前端黑科技）
2. **3分钟上瘾**：答题→错题→AI讲解→复习的闭环心流
3. **30秒记住**：一个独家标签——"哦那个不需要后端也不需要登录、打开就能刷题、还能看3D分子和生物动画的生物竞赛网站"

## 一、产品定位（重新定义：从"工具"到"体验"）

### 1.1 一句话定位（路演版）
&gt; **BioQuest——打开浏览器就能用的生物竞赛私教，不需要注册、不需要付费、不需要服务器，所有数据只在你的设备上。**

### 1.2 核心差异化（3个独家标签）

| 标签 | 内容 | 评委记忆点 |
|------|------|-----------|
| **零摩擦** | 打开即用，不需要登录，不需要配置，不需要等加载 | "我这辈子没见过这么干脆的学习网站" |
| **本地智能** | 即使不连服务器，也有智能错题分析、知识追踪、记忆算法；配了Key还能有AI私教 | "纯前端居然也有智能，不是套壳ChatGPT" |
| **看得见的生物** | 7个细胞级动画+6个交互实验+3D分子浏览+基因组浏览器，把课本里看不见的东西"做出来" | "生物居然能这么学，比课本直观100倍" |

### 1.3 社会价值落地（从文案到功能）

v1的"生物守护计划"是空泛文案；v2要让社会价值**可感知、可交互、可演示**：

- **教育公平落地**：
  - 首页展示"已帮助XX位同学学习"（本地统计+匿名计数，用免费的Supabase只读计数或直接本地演示数据）
  - **乡村科普模式**：设置→开启"低流量模式"，关闭图片自动加载、禁用视频动画，适合网络差的地区
  - 题库完全免费，无任何付费墙、无任何功能锁
  
- **生物多样性科普**（从文案到功能）：
  - 在知识图谱中加入"生物多样性"专题节点
  - 每个濒危物种知识点配一张插画+保护现状（IUCN红色名录等级）
  - 答对相关题目弹出"你已了解+1种濒危生物"微成就
  - 做一个"濒危物种小卡片"收集系统——做题收集物种卡，有收集感

## 二、Wow Moment设计（3个让评委叫绝的瞬间）

v2最大的升级是**刻意设计演示爆点**。以下3个Wow Moment必须做到：

### Wow Moment 1：首页——"打开即惊艳"的第一印象

**问题**：v1首页是普通的Hero+倒计时+卡片，和一般教育网站没区别。

**v2方案：可交互的"细胞呼吸"粒子动画作为首页背景**

- 不是纯装饰——你可以**点击粒子**，会弹出对应的细胞结构名称和一句话介绍
- 粒子隐喻细胞中的分子运动：葡萄糖分子、ATP、酶、氧气、二氧化碳...不同颜色的粒子在流动碰撞
- 鼠标移动会产生"扰动"，粒子流会绕开你的鼠标（隐喻细胞膜的选择透过性）
- 文字："你正在看到的是细胞呼吸的微观世界——欢迎来到BioQuest"
- **技术亮点**：纯Canvas实现，60fps，粒子系统+力场，零外部依赖
- **演示效果**：路演时第一秒打开网站，评委还没听你说什么，眼睛已经被吸引了

### Wow Moment 2：错题本——"AI讲题"的震撼时刻

**问题**：v1的AI讲解只是"配了Key能聊天"，不惊艳。

**问题2**：v1要求用户自己配Key——评委体验时可能没Key，就看不到AI功能。

**v2方案：本地AI+渐进式AI+演示兜底三重保障**

1. **零Key也能AI讲题**：集成Transformers.js在浏览器端运行一个小模型（如Qwen2-0.5B-int4或DistilBART），做基础的"知识点讲解"——不需要API Key！这才是真·纯前端智能！
   - 模型大小控制在200-500MB（懒加载，进入错题本时提示是否下载AI增强包）
   - 如果用户不想下载，有纯规则引擎的"考点解析"兜底（从题库的解析字段提取）

2. **AI讲解可视化**：不是纯文字——AI讲题时同步生成一张Mermaid流程图（如"光合作用的过程"），或在侧边知识图谱上高亮相关节点并扩散
   - 例：你问"为什么减数分裂会发生基因重组？"，AI回答时知识图谱对应节点发光，动画展示"交叉互换"的过程

3. **演示兜底**：飞书问卷提交时，提供一个**预配置了测试Key的体验入口**，或者内置"演示模式"——点击AI讲解时播放预录制的精彩回答（标注"演示模式"，诚实不欺骗）

### Wow Moment 3：学习报告——"数据之美"的震撼

**问题**：v1的学情诊断是雷达图+统计图，常规操作。

**v2方案：你的"学习DNA"3D可视化**

- 用Three.js生成一个**专属的3D学习DNA双螺旋**：
  - 每个碱基对你的一个知识点模块
  - 掌握度决定碱基的亮度/颜色（绿色=已掌握/黄色=薄弱/红色=未掌握）
  - DNA旋转动画，你可以拖拽旋转、缩放
  - 点击某个碱基对展开该模块的详细数据
- 学习报告从"数字表格"变成"你的生命科学学习图谱"——既有视觉震撼，又有数据意义
- 可以导出为图片分享

## 三、核心功能升级（从"可用"到"好用"到"离不开"）

### 3.1 Onboarding：90秒从新人到熟手

**问题**：v1没有首次引导，评委打开不知道干嘛。

**v2方案：3步Onboarding（首次访问显示）**

1. **第1步（5秒）**：半透明遮罩+Tooltip："这是首页——点这里直接开始刷题"（指向「开始刷题」按钮）
2. **第2步（可选）**："想先试试？我们为你准备了一道精选例题"→直接进入单题模式，做完即走
3. **第3步**："你的进度会自动保存在这个浏览器里——随时回来继续"
- 提供「跳过引导」按钮，但数据显示完成Onboarding的用户留存率高3倍
- 右上角"?"可随时重新查看引导

### 3.2 答题体验升级：心流设计

**v1答题只是"看题→选项→对错"，v2要打造"刷题心流"：**

| 升级点 | 设计 |
|-------|------|
| **无刷新切换** | 答对自动下一题（1秒延迟，绿色对勾反馈后滑动切题），不需要点按钮 |
| **键盘流优化** | 1/2/3/4选选项→自动判分→1秒后自动下一题；全程不用鼠标 |
| **连击反馈** | 连续答对5题→屏幕顶部出现"5连对！🔥"；连续10题→更炫的微动画（不浮夸） |
| **错题不打断** | 答错时红色抖动+解析自动展开，但不强制停留——按Space或点"继续"即可下一题 |
| **进度条仪式感** | 每做10题进度条有特殊节点；完成一组（20题）显示小总结 |
| **题目预加载** | 做当前题时预加载下一题的图片/KaTeX，切题零等待 |

### 3.3 生物动画升级：从"演示"到"交互"

v1的生物动画是"播放-暂停-看"，v2要变成"可以玩"：

- **可控参数**：如"光合作用"动画，你可以调节光照强度、CO2浓度，看到动画中反应速率实时变化
- **"你问我答"模式**：动画暂停，弹出问题"如果此时停止光照，ATP和NADPH浓度会怎么变？"——答对继续
- **标注模式**：点击动画任意结构，弹出标注+知识点+相关题目
- **对比模式**：有丝分裂vs减数分裂并排播放，差异部分高亮闪烁
- **技术保障**：所有动画用Canvas实现，60fps，移动端降帧到30fps省电

### 3.4 虚拟实验室升级：从"步骤引导"到"自由探索"

- **自由模式**：除了步骤引导模式，增加"自由实验"——器材摆在台面上，你可以随便拖、随便组合，AI会告诉你"你在做什么、会发生什么"（如果有Key）或规则引擎判断
- **实验错误后果**：比如加热试管没预热→试管破裂动画→"玻璃仪器受热不均会炸裂哦"
- **实验器材图鉴**：所有器材可以点击查看"这个器材叫什么、在真实实验中怎么用"
- **实验报告可分享**：生成漂亮的实验报告图片（Canvas绘制），可下载

### 3.5 知识卡片升级：从"翻卡片"到"记忆魔法"

- **卡片3D效果**：真正的CSS 3D翻转，有阴影、有光照感
- **记忆曲线可视化**：卡片背面下方显示一个小的记忆曲线示意图，标注"你将在X天后复习这张卡"
- **快捷操作**：翻卡后直接按1/2/3/4自评，不需要点按钮，0.5秒完成一张
- **"快速复习"模式**：10张卡一组，像Tinder一样左滑（不会）右滑（会），极速刷完

### 3.6 知识图谱升级：从"节点图"到"知识宇宙"

- **节点有"呼吸"动画**：近期复习过的节点微微呼吸闪烁
- **掌握度光晕**：已掌握的节点有绿色光晕向外扩散
- **路径推荐**：点击薄弱节点→显示"建议学习路径"：节点A→节点B→节点C（高亮路径动画）
- **搜索即定位**：输入"光合"→相关节点逐个亮起，像点亮星座一样
- **全屏模式**：点"全屏"按钮进入知识宇宙沉浸式浏览

## 四、技术架构升级（从"能跑"到"炫技"）

### 4.1 本地AI——真·纯前端智能（最炸技术点）

| 层 | 技术方案 | 说明 |
|----|---------|------|
| **Tier 0（零Key，所有人可用）** | 规则引擎+模板生成 | 错题解析从题库解析字段提取；BKT知识追踪纯算法；学习报告规则生成 |
| **Tier 1（零Key，可下载）** | Transformers.js + Qwen2-0.5B-instruct-int4 | 进入错题本时提示"下载本地AI增强包（约300MB），获得AI私教讲解" |
| **Tier 2（自带Key）** | 前端直连6家LLM（DeepSeek/智谱等） | 现有方案保留，用户自配Key |

**关键：Tier 1让评委在没Key、没网的情况下也能看到AI效果——这才是纯前端的真正实力。**

### 4.2 性能极致——Lighthouse 100分目标

| 指标 | v1目标 | v2目标 | 手段 |
|------|-------|-------|------|
| LCP | &lt;2s | &lt;1.2s | 关键CSS内联；首屏HTML直出；字体子集化（只包含常用字+生物术语） |
| FID/TBT | &lt;100ms | &lt;50ms | 路由懒加载；非关键JS defer；Web Worker处理AI/算法/数据计算 |
| CLS | &lt;0.1 | 0 | 所有图片/容器定宽定高；字体font-display:optional |
| 首屏JS体积 | &lt;200KB | &lt;100KB gzip |  treeshake；只加载核心路由JS；vendor tree-shake |
| 离线可用性 | 核心功能 | 100%核心+80%增强 | Service Worker预缓存所有核心模块；题库JSON增量缓存 |

**字体优化**：当前LXGW WenKai woff2有7.6MB，太大了。
- 方案：用fonttools子集化，只包含常用3500字+生物术语（约2000字），字体缩小到1.5MB以内
- 或者：首屏用系统字体（-apple-system, "PingFang SC", "Microsoft YaHei"），标题用web字体异步加载

**Web Worker多线程**：
- FSRS调度计算→Worker
- BKT/IRT知识追踪计算→Worker
- Transformers.js AI推理→Worker（不阻塞UI）
- 题库搜索/过滤→Worker
- 数据导出压缩→Worker

### 4.3 架构重构——可展示的代码质量

**v1是面条代码，v2要让评委（如果看代码）觉得"这小孩架构不错"：**

```
src/
├── core/                    # 核心层（纯逻辑，无DOM）
│   ├── fsrs.js             # FSRS算法封装
│   ├── bkt.js              # BKT知识追踪
│   ├── scheduler.js        # 复习调度器
│   ├── quiz-engine.js      # 答题判分引擎
│   └── stats.js            # 统计计算
├── data/                    # 数据层
│   ├── db.js               # Dexie.js初始化
│   ├── repositories/       # 数据仓库模式
│   └── migrations/         # 版本迁移
├── ai/                      # AI层
│   ├── local-ai.js         # Transformers.js封装
│   ├── llm-client.js       # 外部LLM客户端
│   ├── prompt-templates/   # Prompt模板
│   └── ai-fallback.js      # 规则引擎兜底
├── ui/                      # UI层（组件化，原生JS组件）
│   ├── components/         # 可复用组件（Card/Modal/Toast/Chart等）
│   ├── pages/              # 页面（home/practice/exam/...）
```

**注意**：不强行上React/Vue——原生JS组件化即可，减少runtime开销，展示"我能写出好架构不需要框架"的能力。

### 4.4 离线能力升级——真PWA

- 首次访问后，核心模块全部缓存，断网完全可用
- 题库数据分片缓存：按模块缓存，做哪个模块下哪个模块的题
- 后台同步：联网时静默更新题库（如果有新版本）
- PWA安装后，桌面图标+启动画面+独立窗口，和原生App一样
- 添加到主屏幕引导：iOS/Android分别提示

## 五、体验打磨——魔鬼在细节里（50个微细节）

以下细节每个加0.2-1分，但加起来就是"好用"和"惊艳"的差距：

1. **答题时自动隐藏Header**，给题目更多空间，向上滚动时Header再出现
2. **选项hover/选中效果**有弹簧般的弹性动画（CSS cubic-bezier）
3. **答对时**除了绿色对勾，有非常轻微的触觉反馈（navigator.vibrate(20)，手机上）
4. **答错时**不做红色叉（太挫败），而是温柔的橙色提示+"没关系，看看解析"
5. **题目切换**有淡入淡出+轻微位移动画，不是突兀替换
6. **长题目**自动记住阅读位置，切回来不跳到顶部
7. **图片题**支持点击放大、pinch缩放（手机双指）
8. **LaTeX公式**渲染后有淡入效果，不闪烁
9. **夜间模式**做真正的"暗黑"——不是反色，是深绿/深蓝黑，不刺眼
10. **主题色**除了默认鼠尾草绿，加2-3套主题（琥珀/靛蓝/玫红）
11. **倒计时**最后10秒数字才变红，不是一上来就红（制造真实紧张感）
12. **交卷**时试卷往上收的动画+分数"盖章"效果
13. **错题本**的卡片有"厚度"，堆叠效果像真实卡片
14. **知识图谱**节点hover有光晕，连线变粗
15. **搜索题目**时输入即搜索，防抖300ms，结果高亮关键词
16. **数据导出**有进度条，导出完成有"文件已准备好"动画
17. **数据导入**有校验，损坏的文件给出明确错误
18. **删除数据**是"输入DELETE确认删除"，防止误触
19. **AI思考中**显示打字机"..."动画，不是干等
20. **AI回复**长文自动滚动到底部，但用户手动上滚后不强制滚动
21. **快捷键提示**在对应按钮上hover显示（如"[空格]翻转"）
22. **移动端手势**：左滑下一题、右滑上一题、双击卡片翻转
23. **横屏提示**：考试/实验时建议横屏使用（不强制）
24. ** idle超时**：5分钟无操作暂停番茄钟/考试计时
25. **回到顶部**按钮：滚动超过2屏后出现，点击平滑回顶
26. **锚点导航**：长解析页有目录锚点（如果解析很长）
27. **复制题目**：点击"复制"按钮复制题目+解析为Markdown
28. **分享卡片**：答题后可以生成"我在BioQuest做对了X题"的分享图片（Canvas绘制）
29. **音量控制**：AI朗读/Web Speech API的音量/语速可调
30. **网络状态**：顶部右上角有微小的联网/离线指示器
31. **更新提示**：Service Worker更新后提示"新版本可用，点击刷新"

## 六、TRAE实践——讲一个好故事（15%的分数在这里）

TRAE实践不是"截3张聊天记录"就行——评委要看的是**"你真的用TRAE解决了问题"**，要有**故事性**。

### 6.1 需要准备的材料

| 材料 | 内容要求 | 数量 |
|------|---------|------|
| Session ID | 关键开发节点的真实Session | ≥5个（不是3个，越多越真实） |
| 开发截图 | TRAE界面截图，显示关键对话/代码生成/调试过程 | ≥8张 |
| 开发故事 | 一篇有起伏的"我是怎么用TRAE做BioQuest"的记叙文 | 1篇，社区发帖用 |

### 6.2 故事线设计（起承转合）

**起：为什么做这个？**
- 我是生物竞赛生，发现市面上的刷题软件要么要付费、要么要注册、要么体验差、要么数据不在自己手里
- 我想要一个"打开浏览器就能刷题"的工具——于是我打开了TRAE

**承：TRAE帮我做了什么？（重点）**
- **第一天**：我对TRAE说"帮我做一个生物竞赛刷题网站，纯前端，不需要后端"→它生成了首页和答题功能的雏形，我惊讶于速度
- **第一个难题**：题库JSON有几千道题，手写数据结构会疯→TRAE帮我设计了数据模型，还写了数据清洗脚本
- **第二个难题**：FSRS间隔重复算法太复杂，我研究了两天没搞懂→把ts-fsrs文档喂给TRAE，它帮我封装成了兼容层，连单元测试都写了
- **第三个难题**：Canvas生物动画（有丝分裂）写了一周还是卡→TRAE帮我分析性能瓶颈，用requestAnimationFrame重写了渲染循环，从20fps优化到60fps
- **第四个难题**：IndexedDB API太繁琐→TRAE推荐用Dexie.js并帮我封装了数据层，还处理了版本迁移
- **AI功能**：TRAE帮我写了6家LLM的统一封装层，处理SSE流式、错误重试、Markdown渲染
- **Bug调试**：有一个"刷新后答题进度丢失"的Bug我找了3小时→TRAE看了代码后指出是我JSON序列化时丢了Date对象，帮我修复

**转：遇到了什么坑？怎么解决的？**
- TRAE不是万能的——它生成的知识图谱力导向布局一开始有性能问题，我和TRAE来回对话了5轮，最终从每次全量重绘优化到只更新变化的节点
- 它一开始给的虚拟实验室拖拽逻辑不对，我给它看了Figma设计稿截图（多模态），它理解后修正了
- 最惊险的是：Supabase依赖导致无网络时白屏，TRAE帮我设计了完整的离线降级方案，最后我干脆决定完全去掉后端，所有数据本地存储——这是v2的关键决策

**合：最终成果**
- 从0到1，TRAE陪我写了XX天，XX%的代码是AI生成/辅助的
- 最大的感受：TRAE不只是代码生成器，是一个能讨论架构、Debug、一起思考的"搭档"
- 放一张最终产品和第一天原型的对比截图

### 6.3 Session ID选择策略

按开发阶段选Session，展示完整过程：
1. 项目初始化：第一次对话，生成项目骨架
2. 核心功能：FSRS算法集成的对话
3. 技术难点：Canvas性能优化的对话（来回多轮）
4. Bug修复：那个找了3小时的Bug的修复对话
5. 架构重构：决定去掉Supabase、纯本地方案的对话

## 十、风险预案与降级策略

即使做了万全准备，也要有Plan B：

| 风险 | 预案 |
|------|------|
| 本地AI模型（Transformers.js）加载太慢/太大 | 默认不加载；用户主动点击"下载本地AI"才加载；首屏零AI依赖 |
| 3D分子/基因组浏览器加载失败 | 显示"此功能需要联网，你可以先体验其他功能" |
| PhET iframe被墙/加载慢 | 显示加载超时提示，引导去其他功能 |
| Safari兼容性问题 | 核心功能在Safari可用；WebGL/AI等高级功能检测不支持则优雅降级 |
| 评委打不开链接/链接失效 | 同时部署到Vercel+GitHub Pages+Netlify三个地方，提供3个链接备用；同时准备录屏视频兜底 |
| 评委没配API Key看不到AI | 演示模式+本地AI+规则引擎三重兜底；飞书问卷里说明"AI功能为可选增强，核心功能无需Key" |
